# Draw.io Layout Guidelines

## 1. Start with the message
Write one sentence describing what the diagram should help the reader understand. Remove elements that do not support that purpose.

## 2. Choose the right view
- Context: system boundary, users, and external systems.
- Container or service: deployable units and their dependencies.
- Component: internal modules and interfaces.
- Deployment: runtime nodes, networks, and infrastructure.
- Data flow: sources, transformations, stores, and destinations.
- Sequence: interactions ordered over time.
- Process: decisions, actions, and handoffs.

## 3. Geometry and spacing
- Align nodes to a consistent grid.
- Keep similar node types at consistent dimensions.
- Use generous page margins and internal container padding.
- Avoid placing text near rounded corners or container borders.
- Ensure connector paths do not pass through labels or node interiors.
- Prefer short, direct paths and avoid unnecessary bends.

## 4. Typography and contrast
- Use one primary font family.
- Establish a small type scale for titles, node labels, and annotations.
- Use concise labels and line breaks intentionally.
- Check contrast in both light and dark viewing contexts.
- Pair color with labels, line styles, or shapes to preserve meaning.

## 5. Connectors
- Use arrows only when direction matters.
- Label ambiguous relationships.
- Keep connectors behind nodes.
- Use explicit source/target references when connecting cells.
- Avoid bidirectional arrows when two clear directional edges are easier to understand.

## 6. Review
Inspect the exported preview at normal presentation size. Check for clipping, overlap, visual imbalance, confusing direction, inconsistent spacing, and excessive detail.
